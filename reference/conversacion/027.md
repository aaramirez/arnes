## Podríamos organizarlos como Domain Packs

Ahí creo que aparece una arquitectura todavía más clara:

```text
                         GENERIC HARNESS
                               │
          ┌──────────┬─────────┼─────────┬──────────┐
          ▼          ▼         ▼         ▼          ▼
        Book      Coding    Research    Data     Support
        Pack       Pack       Pack      Pack       Pack
          │          │         │         │          │
          ▼          ▼         ▼         ▼          ▼
        Book      Coding    Research    Data     Support
       Harness    Harness    Harness   Harness    Harness

          ┌──────────┬─────────┼─────────┐
          ▼          ▼         ▼         ▼
        Sales     Finance     NOC      Workflow
         Pack       Pack      Pack       Pack
```

Cada `Domain Pack` tendría exactamente las mismas categorías:

```text
DomainPack
│
├── Agents
├── Skills
├── Tools / Capabilities
├── State
├── Context Providers
├── Policies
├── Validators
├── Evals
├── Activation Rules
├── Workflows
├── Business Outcomes
└── UI / Interaction
```

Esto nos permitiría incluso formalizar:

```text
INTERFACE DomainPack

    agents() -> AgentDefinitions

    skills() -> SkillDefinitions

    capabilities() -> CapabilityDefinitions

    policies() -> PolicyDefinitions

    activations() -> ActivationDefinitions

    evals() -> EvaluationDefinitions

    outcomes() -> BusinessOutcomeDefinitions

END
```

El **Generic Harness no sabe qué es una factura, un libro, un pull request, una OLT o una oportunidad de Salesforce**.

Eso pertenece al Domain Pack.

   ↓
