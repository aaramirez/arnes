Dime cual librería se usa para el tui en Pi?

Una de las cosas que más me sorprendió es que **Pi NO usa Ink, Blessed, React Ink, Bubble Tea ni ninguna librería TUI existente.**

**Tiene su propia librería TUI**, llamada:

> **`@earendil-works/pi-tui`** ([GitHub][1])

La arquitectura es bastante minimalista.

En lugar de React, los componentes implementan una interfaz simple:

```ts
interface Component {
  render(width: number): string[];
  handleInput?(data: string): void;
  invalidate(): void;
}
```

Cada componente simplemente devuelve un arreglo de líneas de texto para renderizar. ([Pi][2])

---

## ¿Cómo renderiza?

No utiliza un framework.

Hace rendering directamente usando:

* ANSI escape codes
* Differential rendering (solo redibuja las líneas que cambiaron)
* Kitty Keyboard Protocol
* OSC 8 hyperlinks
* soporte para imágenes de Kitty/iTerm2

Es básicamente un motor TUI propio. ([Agent Safehouse][3])

---

## ¿Por qué hicieron eso?

Porque necesitaban capacidades que Ink no ofrece fácilmente:

* editor de texto propio
* overlays
* modales
* streaming del LLM
* actualizaciones parciales muy rápidas
* soporte para miles de renders sin parpadeo
* extensiones que puedan insertar componentes arbitrarios

En lugar de adaptar React al terminal, hicieron un renderer especializado. ([Agent Safehouse][3])

---

## ¿Qué haría yo para nuestro proyecto?

**No copiaría esa decisión en v0.1.**

Pi ya tiene varios años de evolución y mantener un renderer propio es costoso.

Yo empezaría así:

```text
v0.1
---------
Ink (React)
```

o incluso una UI muy sencilla.

Cuando el harness madure:

```text
v0.2
---------
Abstraer la UI
```

```ts
interface UIAdapter {
    render(event: AgentEvent): void;
}
```

Y solo si realmente encontramos limitaciones de rendimiento o flexibilidad, construiría un renderer propio inspirado en `pi-tui`.

---

Después de revisar bastante del código, mi conclusión es que **la verdadera innovación de Pi no está en el TUI**.

Está en estos tres paquetes:

```
pi-ai
      ↓
pi-agent-core
      ↓
pi-coding-agent
```

El TUI es simplemente otra aplicación encima del runtime.

De hecho, si mañana eliminaras completamente el TUI, **el agent loop seguiría funcionando exactamente igual**. Esa es una excelente separación de responsabilidades. ([GitHub][1])
