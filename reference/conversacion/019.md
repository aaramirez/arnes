# 4. Solo entonces escribimos el pseudocódigo

Ejemplo de `AgentLoop`:

```text
FUNCTION runAgent(
    config: AgentConfig,
    state: AgentState,
    execution: ExecutionContext
) -> AgentRunResult

    emit AgentStarted(state.runId)

    WHILE TRUE

        ExecutionController.assertCanContinue(
            state,
            execution
        )

        context =
            ContextEngine.build(
                config,
                state,
                execution
            )

        response =
            ModelGateway.generate(
                ModelRequest(
                    messages = context.messages,
                    tools = config.allowedCapabilities
                ),
                execution
            )

        state.messages.append(
            response.assistantMessage
        )

        IF response.toolCalls.isEmpty()
            state.status = COMPLETED

            emit AgentCompleted(state.runId)

            RETURN AgentRunResult(
                status = COMPLETED,
                output = response.text
            )
        END

        results =
            ToolRuntime.execute(
                response.toolCalls,
                execution
            )

        FOR EACH result IN results
            state.messages.append(
                ToolResultMessage(result)
            )
        END

        state.currentTurn += 1

    END
END
```

El lector puede seguirlo porque cada entidad ya existe.

# 5. El pseudocódigo debe ser tipado

Yo evitaría pseudocódigo excesivamente abstracto.

No:

```text
result = doStuff()
```

Sí:

```text
result: ToolResult =
    ToolRuntime.execute(call, execution)
```

Esto obliga al libro a mantener coherencia.

Incluso podemos usar una sintaxis consistente:

```text
STRUCT
ENUM
INTERFACE
FUNCTION
IF
FOR EACH
RETURN
THROW
EMIT
AWAIT
```

Sin entrar en TypeScript, Python o Java.

# 17. Separar commands, events y state

Otra disciplina importante:

```text
Command

    says something happened

State

```

```text

    ↓
ToolExecuted
    ↓
AgentState updated
```

No mezclarlos.


```text
Architecture Constitution
        ↓
Component Registry
        ↓

        ↓
ADRs
        ↓
Chapter Architecture
        ↓
Pseudocode
        ↓

```

Ese enfoque nos permitiría escribir un libro donde el código no sea una colección de ejemplos, sino la **derivación sistemática de una arquitectura coherente**.
